# D3: C4モデル レベル2(コンテナ)

## 遵守すべき重要ルール

1. **レベル1 を変えない**: 人(`ACT-*`)・外部システム(`EXT-*`)・対象システムの境界はレベル1 に従う。過不足があれば本書で辻褄を合わせず、レベル1 の見直し要否をユーザーに確認する。
2. **未決で残さない**: コンテナの分割・連携方式は、ADR に決定があればそれに従い、なければレベル1 シーケンスから設計して埋める。ADR に基づかない箇所には要確認マーカーを付す。
3. **技術を書かない**: 言語・フレームワーク・製品・クラウドサービス・プロトコルの名称は、図にも表にも書かない。
4. **ID を振り直さない**: `CNT-*` はレベル2 シーケンスのライフラインから参照される。採番済みの ID は変えず、欠番も再利用しない。
5. **画面は SPA と BFF に分ける**: 利用者の画面ごとに、ブラウザで動く SPA と、サーバーで動く BFF を別々のコンテナとして置く。
6. **業務起点で、細かすぎないマイクロサービスにする**: 業務サービスは業務の流れを起点に分け、ドメインごとに機械的に分けるほど細かくしない。業務で分けたうえで、データアクセス要件やその他の要件を満たせるかを確かめる。

## 処理

### 1. 分岐する
- `docs/D3.system-design/c4-level2-container.md` が存在しないなら、§2(新規作成)に進む。
- それ以外なら、§3(更新)に進む。

### 2. 新規作成

#### 2.1 上流を読む

レベル1 シーケンスを読み、UC ごとに、操作する人・外部とのやり取り・記録対象・利用者の操作を起点としない処理を控える。もし ADR が存在するなら、承認済みの決定だけを採用する。

#### 2.2 コンテナを設計する

コンテナは独立して実行・デプロイされる単位とし、1 つが止まっても他の業務を続けられるように分ける。

- 業務処理は、レベル1 シーケンスの工程間の引き渡しを境界に業務サービスへ分ける。同じ手続きの中で結果を待ち合わせる業務は同じサービスに置き、外部サービスへの依頼と結果待ちが続く業務は 1 つのサービスにまとめる
- 業務サービス間の引き渡しは非同期とし、他の業務サービスを同期で呼ばない
- 利用者の入口(SPA・BFF)は、一緒に止まってよい業務の利用者ごとに分ける
- 複数の業務サービスが共通で依存する処理は作らず、担当するサービスに持たせる。もし通知のように業務を止めずに後から処理できるものなら、共通のコンテナに分けてよい
- 計算負荷の特性が大きく異なる処理は、業務サービスから切り出す
- 各業務サービスのデータは専有とし、データストアは図に描かない

いずれのコンテナにも割り当たらない UC・人・外部システムが残るなら、分割を見直す。

#### 2.3 連携方式を決める

線は呼び出す側から呼び出される側へ引き、同じ組のやり取りは 1 本にまとめる。もし ADR に決定があるなら、それに従う。そうでないなら、応答を待つ場合は同期、待たない場合は非同期とする。

#### 2.4 図と表を埋める

- 図は `flowchart LR` で描く(C4 専用記法は使わない)。人・外部システムの `subgraph` はレベル1 と同じ括りにする。
- 名称は、業務サービスは「業務名+サービス」、SPA は「利用者名+用SPA」、BFF は「利用者名+用BFF」とし、業務担当者が読んで分かる語にする。
- BFF からの線は、その利用者の UC が扱う業務サービスごとに 1 本ずつ引く。
- 工程間で引き渡しを行う業務サービスは `subgraph` で囲み、囲みの中の全サービスに共通する線(通知・証跡へのイベント)だけを囲みから 1 本で引く。
- もし外部システムが対象システムの境界の右に並ばないなら、非表示の線(`~~~`)で位置を整える。
- `CNT-*` は図の上から順に 1 から振る。
- ノード名と線のラベルは 1 行 12 文字以内で改行し、線のラベルにはやり取りする内容と連携方式を書く。もし ADR に基づかない連携方式や、根拠となる UC が無い線があるなら、図の直後のブロック要確認マーカーにまとめる。
- 設計根拠列には、ADR に基づくなら ADR の ID、そうでないなら分割の根拠にした UC と特性を書く。
- `sidebars.ts` の「D3. システム設計」カテゴリに登録する。

### 3. 更新

- 上流(レベル1・レベル1 シーケンス・ADR)で変わった箇所に関わるコンテナと線だけを §2 の手順で見直す。
- 新しいコンテナには全体の最大値の次の ID を振る。不要になったコンテナは行を削除し、ID を欠番にする。
- もしコンテナの分割・統合で既存 ID の引き継ぎ先が決まらないなら、ユーザーに確認する。

## 完成時のセルフチェック

- 図の `ACT-*` / `EXT-*` の集合が、レベル1 §登場要素の集合と一致している
- レベル1 シーケンスの全 `UC-*` が、コンテナ表の関連 UC 列に現れている
- 図のコンテナのノードが、コンテナ表の行と過不足なく対応している
- ADR に基づかない設計根拠・連携方式に要確認マーカーが付いている
- `CNT-*` に重複が無く、更新時は既存の ID とコンテナの対応が変わっていない
- `{{` が残っていない
