# D2: 画面一覧

## 遵守すべき重要ルール

1. **ID を振り直さない**: `SCR-*` は Figma のフレームと本書を結ぶキーになる。採番済みの ID は変えず、欠番も再利用しない。追加時は全体の最大値の次を採番する。
2. **機能一覧に無い画面を作らない**: すべての画面は 1 つ以上の `FUNC-*` に裏付けられる。必要な機能が機能一覧に無ければ、画面を作らずユーザーに報告する。

## 処理

### 1. 分岐する

- もし機能一覧またはユースケース一覧が存在しないなら、先に作成が必要な旨を伝えて終了する。
- そうでなく、`docs/D2.system-requirements/screen-list.md` が存在しないなら、§2(新規作成)に進む。
- それ以外なら、§3(更新)に進む。

### 2. 新規作成

#### 2.1 画面の要否を判定する

機能一覧の各 `FUNC-*` について、利用者が入力・選択・閲覧する機能であれば画面を起こす。システムが自動で実行する機能、外部サービスの画面で操作する機能、帳票・メールそのものであれば画面を起こさない。

#### 2.2 画面候補を出す

UC ごとに操作の流れをたどり、画面候補を出す。同じアクターがその場で処理するイレギュラーは別の画面にせず、元の画面の画面概要に含める。単純な確認ダイアログやトーストは候補にしない。

#### 2.3 まとめる・分ける

1 画面はワイヤーフレーム 1 枚の単位とする。アクターや UC が違っても、同じ業務情報を表示する候補は 1 画面にまとめる。アクターによる一部の表示・操作の違いは、画面を分けずに画面概要に書く。

以下のいずれかに当たる場合だけ画面を分ける。

- UI/UX 方針が利用者種別ごとの体験の分離を求めている
- データアクセス要求により、アクターごとに見せる情報のまとまりが異なる
- 表示・操作が大きく異なり、ワイヤーフレーム 1 枚で描けない

デバイスの違いや、空状態・エラー表示などの状態違いでは分けない。

#### 2.4 各列を埋める

| 列 | 埋め方 |
|---|---|
| **ID** | `SCR-<連番>`。並び順どおりに 1 から振る |
| **画面分類** | 関連 UC の「ドメイン / 区分」。複数ドメインにまたがる場合は `横断` |
| **画面名** | `〜画面` の体言止め。本書内で一意にする |
| **画面種別** | `一覧` / `詳細` / `入力` / `確認` / `完了` / `ダッシュボード` / `ダイアログ` / `案内`(エラー・次行動提示など表示専用)のいずれか |
| **画面概要** | 画面の目的と主な表示情報・操作を 1〜2 文。遷移先・レイアウトや、画面の外で行うことは書かない |
| **利用アクター** | 画面を実際に操作・閲覧するアクター |
| **対象デバイス** | 利用アクターの PRD §利用形態 の端末(`PC` / `タブレット` / `スマートフォン`) |
| **関連 UC / 関連 FUNC** | 画面が関わる `UC-*` / `FUNC-*` |

#### 2.5 並び順・ラベル・サイドバー

- ユースケース一覧のドメイン順・UC 順・操作の流れの順に並べ、`横断` を最後に置く。
- 関連 FUNC がすべて `[フェーズ2]` の画面は、画面名に `[フェーズ2]` を付ける。
- `sidebars.ts` の機能一覧の直後に登録する。

### 3. 更新

- 上流で変わった `FUNC-*` / `UC-*` に関わる行だけを §2 の手順で見直す。
- 不要になった画面は行を削除し、ID を欠番にする。
- 削除・統合・改名した画面があれば、最後に `SCR-*` と画面名をユーザーへ伝える(Figma 側の整理に使う)。

## 完成時のセルフチェック

- 関連 FUNC が空の画面が無い
- `SCR-*` に重複が無く、更新時は既存の ID と画面の対応が変わっていない
- `{{` が残っていない
