# D9: テストデータ要件定義書

## 遵守すべき重要ルール

1. **テーブル名・カラム名は記載しない**: エンティティは ER図の名前で記載する。ER図が無ければ概念データモデルの名前で記載する。
2. **具体の数字と値は記載しない**: 件数は「表示上限を超える件数」のように記載する。氏名・コードのように案件で用意する値の具体は記載しない。
3. **観点一覧の範囲の外に出ない**: 観点一覧に無い観点からデータ要件を作らない。
4. **上流の成果物を直さない**: 上流の漏れや誤りに気づいたら、直さずにユーザーへ伝える。
5. **ID を振り直さない**: 採番済みの `TDR-*` は変えず、欠番も再利用しない。

## 処理

### 1. 分岐する

- もし `docs/D9.test-design/test-perspectives.md` が無いなら、テスト観点一覧が先である旨を伝えて終了する。
- もし `docs/D9.test-design/test-data-requirements.md` が無いなら、§2（新規作成）に進む。
- それ以外なら、§3（更新）に進む。

### 2. 新規作成

#### 2.1 観点の要否を判断する

観点一覧の `TVP-*` を上から見て、前提条件と期待値から、手順を始める前のテストデータの要否を決める。要らない観点は行にしない。

- **要る**: 手順を始める前に、エンティティの存在・状態・件数を満たしておく必要がある。
- **要らない**: 画面操作だけ、入力中の値、当該ケースの登録操作で作るデータ、スタブや環境の状態。

#### 2.2 状態と件数と属性（値）の条件を記載する

2.1 で要るとした観点を上から進め、`TDR-*` は上から通し連番で振る。

- **エンティティ**: 観点の対象を ER図の名前に合わせる。ER図が無ければ概念データモデルの名前を使う。
- **必要な状態**: 前提条件と期待値から取る。状態が要らなければ「—」とする。
- **件数**: 前提条件が求めているデータ件数を記載する。具体の数字は記載しない。表示上限の有無は画面設計書を見る。画面設計書が無いときは、シーケンスとワイヤーフレームを見る。
- **属性（値）の条件**: 前提条件と期待値のうち、状態にも件数にも入らない条件を記載する。要らなければ「—」とする。バッチの対象条件はバッチ一覧を見る。バッチ一覧が無いときは、バッチの対象条件は無いものとして扱う。条件は1つずつ短く記載し、複数あるときは「／」でつなぐ。
- **依存**: ER図の関連から記載する。ER図が無ければ概念データモデルを使う。無ければ「—」とする。
- **関連テスト観点**: 今見ている `TVP-*` を記載する。
- **参照元**: 見た成果物とその中の箇所を記載する（「ER図 注文／画面設計書 注文一覧画面 項目」等）。

#### 2.3 重複をまとめる

同様のテストデータを使い回せる行は1行にする。まとめたあと、エンティティ、必要な状態、件数の順に並べ、`TDR-*` を上から通し連番で振る。

- **件数**: 「判定に足りる件数」と「複数件」は、複数件の1行にする。
- **必要な状態**: 未完了だけ・完了だけの行は、混在の行に使い回せるならまとめる。
- **属性（値）の条件**: 一方の条件をもう一方の観点にも使い回せるなら1行にする。
- **0件**: 0件の行は1行にまとめる。
- 表示上限を超える件数の行と、一方の条件をもう一方に使い回せない行はまとめない。

#### 2.4 仕上げる

「完成時のセルフチェック」を実施する。

### 3. 更新

- インプットした成果物で変わった箇所に関わる行を §2 の手順で見直す。新しい要件には最大値の次の ID を振り、不要になった要件は行を削除する。
- もし要件を追加・削除・変更したなら、テストデータ作成ツールの見直しが必要になる旨をユーザーに伝える。

## 完成時のセルフチェック

- 観点一覧のうち、手順を始める前にテストデータが必要な `TVP-*` が、いずれかの行の関連テスト観点に現れている
- 各行の関連テスト観点に、観点一覧に無い `TVP-*` が現れていない
- 画面操作だけ・入力中・当該ケースの登録操作で作るデータ・スタブや環境の状態だけの観点が、関連テスト観点に現れていない
- 同様のテストデータを使い回せる行が、複数行に分かれていない
- テーブル名・カラム名が記載されていない
- 氏名・商品コードなどの業務データの具体値と、桁数・件数の仕様具体値が記載されていない
- 全行のエンティティ・必要な状態・件数・属性（値）の条件・依存・関連テスト観点・参照元が埋まっており、「同上」等で省略されていない
- 参照元に挙げた成果物がインプットする成果物のいずれかである
- `TDR-*` に重複が無く、行がエンティティ、必要な状態、件数の順になっている。更新時は既存の ID と要件の対応が変わっていない
