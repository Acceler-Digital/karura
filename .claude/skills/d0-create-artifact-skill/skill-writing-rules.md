# 成果物スキルの書き方

成果物スキル(`.claude/skills/<skill-name>/`のSKILL.md・template.md)を作成・更新するときの規約。

## template / SKILL / CLAUDE.mdの責務分担

三者は内容を重複しないようにする。同じ内容が二箇所に現れている場合は設計上の不備とみなす。

| 置き場所 | 書くもの | 書かないもの |
|---|---|---|
| **template.md** | 文書の骨組みのみ — タイトル・章/表の構成(列名・並び)・プレースホルダ行。冒頭HTMLコメントはSKILL.md / CLAUDE.mdへの参照案内に留める | 振る舞いルール(埋め方・粒度・分割/集約の判断・チェック観点)、汎用規約の再掲 |
| **SKILL.md** | **固有**の振る舞い — 生成トリガ、input/output、記述粒度、分割/集約単位、各列の埋め方 等 | descriptionと重複する役割/位置づけ、templateに従えば自明な章構成、他成果物共通の汎用規約(CLAUDE.mdに集約) |
| **CLAUDE.md** | プロジェクト**横断**の汎用規約 — プレースホルダ書式・HINT記法・要確認マーカー・文体・ID表記・コミット規約 等 | 個別成果物固有のルール |

## SKILL.mdの書き方

SKILL.mdには「その成果物を生成するために実際に必要な固有の振る舞い」だけを**最小限**に書く。書かなくてもClaudeが上流を読めば同じ判断をする事項や、一般的な設計慣習は書かない。各情報は一意の置き場所を持ち、本文に一度だけ現れる。

### 章構成

以下の章をこの順で置く。

| 章 | 書くもの |
|---|---|
| 遵守すべき重要ルール | 破ると成果物や下流が壊れる、当該成果物固有の少数のルール |
| インプットする成果物 | 上流成果物のパスと、そこから何を引くか |
| アウトプットする成果物 | 成果物のパス |
| アウトプットに使用するテンプレート | テンプレートのパス |
| 引数 | 受け取る引数とその意味。引数が無ければ章ごと置かない |
| 処理 | 生成・更新の手順と判断。分岐は「もし〜なら / そうでなく〜なら / それ以外なら」の形で書く |
| 完成時のセルフチェック | 突き合わせで確かめられる項目(網羅・参照切れ・ID重複・プレースホルダ残存 等)だけ |

- **引数**: 成果物の有無など、状態から判定できることは引数にしない。引数の章には意味だけを書き、受け取った後の動作は処理の分岐に書く。
- **レビュー動作を持たせない**: スキルは新規作成と更新だけを扱う。上下流の整合確認は、成果物ごとのスキルではなくプロジェクト横断のトレーサビリティ管理で行う。

### 書かないもの

- **descriptionと重複する内容**: 役割・位置づけ・発火条件はdescriptionが持つ。本文冒頭に成果物の紹介文・位置づけ段落を置かない。
- **成果物の章構成**: 成果物の構造(章立て・表の列名と並び)はtemplate.mdの骨組みに従うため自明。SKILLは「どう埋めるか」だけを書く。
- **自明なinput/output**: 更新時に当該成果物自身を読む、等の自明な項目は列挙しない。
- **同一ルールの再掲**: 1つの規律は最も適切な1箇所にだけ書く。ルールを処理やセルフチェックで言い直さない。
- **上記以外の定型セクション**: 「本書について」「留意事項」「下流伝搬」等を型として置かない。下流の都合で守るべきことは、重要ルールか処理の中に書く。
- **記号的な式によるルール表現**: 「1画面 = A × B」のような略式で書かず、平易な文で書く。

## スキルdescriptionの記述方針

成果物スキル(`.claude/skills/<skill-name>/SKILL.md`)のfrontmatter `description`は**最小限**に保つ。`description`の唯一の役割は**ルーティング判定**(モデルが全スキルのdescriptionだけを読み比べ、どれを発火すべきか決める)であり、判定に効かない情報を記載するとノイズになって発火精度を下げてしまうため。

### descriptionに書くもの

- **役割**: 何をする成果物か(例: 「機能一覧の新規作成・更新を支援する」)
- **発火条件**: いつ呼ぶか(例: 「ユースケース一覧の策定後、機能の洗い出し段階で呼び出す」)
- **区別キー**: 似た成果物スキルと取り違えない最小限のキーワード(例: フェーズ記号`D2`・成果物名・直近の上流成果物名)

目安は**1〜3文**。

### descriptionに書かないもの

- 上流下流・上位下位関係の説明、章構成、列構成
- 記述粒度・分割単位・ID体系・スコープ境界
- 下流成果物への伝搬関係、完成時チェック観点

これらはSKILL.md本文に正規の置き場所がある(本書「SKILL.mdの書き方」を参照)。descriptionはそこへ誘導する看板であり、内容の要約ではない。

### 適用対象

- 全フェーズ・全成果物スキルに適用する
