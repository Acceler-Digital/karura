## 生成規約

以下は本成果物を生成・更新する際に守る規約。

### 分割とファイル構成

- **1 大項目 = 1 ファイル**。IPA の大項目より細かく割らない・粗くまとめない。ファイル名は `<大項目記号>.<大項目名>.md`(記号と名称の間に空白を入れない。例: `A.可用性.md`)。大項目名はグレード表の表記をそのまま引く。
- **ファイル名の先頭に数字を置かない**。Docusaurus は `<数字>.` / `<数字>-` で始まるファイル名を並び順指定と解釈して doc id・URL から除去するため、`sidebars.ts` の参照とファイル名がずれる。大項目記号(`A`〜`F`)は英字なので除去されない。
- 前段(本書について / モデルシステムと前提条件 / 対象範囲と対象外メトリクス / 本書の構成)は **`総則.md`** に置き、大項目ファイルに複写しない。総則は全大項目のレベル値の根拠となるため、各大項目ファイルの冒頭に総則への参照リンクを 1 行置く。
- 見出しレベルは、大項目ファイルで **大項目が `#`・中項目が `##`**。中項目の節は対象メトリクスが 0 件でも削除せず、「対象メトリクスなし」とその理由を 1 文で記す。
- 総則 §本書の構成 に全大項目へのリンクとメトリクス件数を置き、分割後も全体像を 1 画面で追えるようにする。

### ID の通し連番(ファイルをまたぐ)

- `NONFUNC-<連番>` は **全ファイルを通した 1 本の連番**。ファイルごとにリセットしない(分割は物理的な都合であり ID 体系を変える理由にならない)。大項目ファイルの先頭 ID が 1 以外になるのは正しい状態。
- 行を追加する際は、当該大項目の末尾に追記して以降の全ファイルの ID を振り直すのではなく、**全体の最大値の次の番号を採番する**(既存 ID の意味を変えない)。結果として ID がファイル内で不連続になってよい。
- 他の行を参照するときは **ID のみで引き、ファイル間の相対リンクを張らない**(例: 「NONFUNC-7(RPO = 0)と同一根拠」)。分割構成を変えるたびにリンクを張り直す事態を避けるため。ファイル単位の参照(総則へのリンク 等)は相対リンクでよい。

### 準拠フレームワークと項目体系

- 項目体系は **IPA「非機能要求グレード」** に準拠する。6 大項目(A. 可用性 / B. 性能・拡張性 / C. 運用・保守性 / D. 移行性 / E. セキュリティ / F. システム環境・エコロジー)と、その配下の中項目・メトリクスをそのまま章・節・行に写す。
- **大項目・中項目・メトリクス名・項番はグレード表の表記をそのまま引く**。本書側で言い換え・統合・新設をしない。項目体系の見直しが必要と判断した場合は、勝手に変えずユーザーに確認する。
- **レベル値はそのメトリクスに定義されているレベルの範囲内でのみ選ぶ**(メトリクスごとに上限が異なる)。定義にない値・小数・範囲指定を書かない。
- 本書は IPA の項目体系を借りるが、**レベル値と要求内容は本プロジェクトの上流成果物から決める**。グレード表のモデルシステム推奨値をそのまま転記しない(推奨値は §モデルシステムの選択 で基準線として使い、差異を根拠付きで示す)。

### スコープ(D2 の抽象度)

本書が決めるのは **「どの水準を要求するか」まで**。その水準を **どう実現するか(How)は D3 以降** に降ろす。IPA のメトリクスには実現方式に踏み込む語彙を含むものがあるため、以下で線を引く。

| 書く(D2) | 書かない(D3 以降) |
|---|---|
| 稼働率・許容停止時間・RTO / RPO・世代数・保存期間・応答時間・処理件数・データ量 等の**要求水準** | 冗長化構成・クラスタ方式・バックアップ製品・ミドルウェア・機器選定・ネットワーク構成 等の**実現手段** |
| 「業務時間帯の稼働率 99.9%」 | 「AZ 二重化+ロードバランサ配下で N+1 構成」 |
| 「監査ログを 10 年保持し検索可能とする」 | 「オブジェクトストレージの WORM 設定で保持」 |

- 実現手段を書きたくなった場合は、それが要求水準として言い換えられるかを確かめ、言い換えられないなら D3 に降ろして本書には書かない。
- `DOM-COMMON-NFR-5`(クラウドネイティブ前提)により、**F. システム環境・エコロジー の機材設置環境条件系メトリクスの多くは責任分界上クラウド事業者側に帰属する**。該当するものは無理に水準を立てず §対象範囲と対象外メトリクス で「対象外」とその理由を明示する。

### モデルシステムの選択

- 冒頭でモデルシステム(社会的影響が殆ど無いシステム / 限定されるシステム / 極めて大きいシステム)を **1 つ選び、選択理由を明記する**。以降のレベル値はこの選択を基準線として決める。
- 選択理由は BRD の事実(取扱情報の性質・利用者規模・法令適用・KPI)から書く。
- **モデルシステムの推奨レベルと異なるレベルを選んだ行は、選択根拠列の冒頭に `モデル推奨 N からの差異:` と書き、差異の理由を続ける**。基準線からどこをどう動かしたかが行単位で読めることが本書の合意価値であるため、差異を無言で埋めない。

### 対象メトリクスの範囲

- **グレード表の全メトリクスを行として立てることを既定とする**(上流に根拠がない場合も、仮置きのレベル値+要確認マーカーで必ず立てる。根拠がないことを理由に行ごと落とさない)。
- 対象外とするのは以下に限る。それ以外の理由で落とさない。
    - 責任分界上、本プロダクトの要求として立てられないもの(クラウド事業者・外部サービス側に帰属)
    - 本プロダクトの提供形態に存在しない構成要素に係るもの(自社調達しない機材・端末 等)
- 対象外メトリクスは **中項目単位で件数と理由を残す**(何を見送ったかが後から追える状態にする)。

### 各列の埋め方

| 列 | 埋め方 |
|---|---|
| **ID** | `NONFUNC-<連番>`(採番規則は §ID の通し連番)。ID に大項目記号を含めない。分類は項番列が持つ |
| **項番** | `<大項目記号>.<中項目>.<小項目>.<メトリクス>` の 4 階層(例: `A.1.1.1` = 可用性 / 継続性 / 運用スケジュール / 運用時間-通常)。グレード表の連番をそのまま引く |
| **メトリクス** | `<小項目名>: <メトリクス名>` の形でグレード表の表記をそのまま引く(例: `サーバ: 冗長化(機器)`)。メトリクス名だけでは対象が特定できないものが多いため、小項目名を必ず前置する。言い換え・省略をしない |
| **重要項目** | IPA グレード表で重要項目とされているものに `◎`、それ以外に `−`。グレード表の指定と照合できていない場合は `◎` を推測で付さず、§本書について で照合未了である旨を明示する |
| **レベル** | 選択したレベル値の数値のみ(例: `3`) |
| **要求内容** | そのレベルが本プロダクトにおいて具体的に何を意味するかを、**業務・システムの固有名詞と実数値** で書く。「高い可用性を確保する」のような水準の読めない書き方をしない。対象を限定する場合は対象範囲(業務時間帯・対象ドメイン・対象連携先)を明示する |
| **選択根拠** | なぜそのレベルかを 1〜2 文。モデル推奨と異なる場合は冒頭に差異表記(§モデルシステムの選択)。上流の記述が根拠なら、どの成果物のどの記述かが特定できる語で書く |
| **関連 ID** | 根拠・適用対象となる他成果物の ID(`DOM-COMMON-NFR-*` / `DOM-COMMON-SEC-*` / `DOM-COMMON-REG-*` / `DOM-AUDIT-*` / `EXT-*` / `FUNC-*` / `ACT-*`)。該当がなければ `−` |

### 数値の出典

- **目標数値は上流から引き、本書で創作しない**。稼働率・レスポンスタイム・スループット・利用者規模・年間件数・保存期間・リリース時期・予算枠 は、いずれも BRD またはドメイン共通要求仕様書に実数がある。まずそこを引く。
- 上流の数値を本書の粒度に展開する場合(例: 年間件数から日次・時間帯別のピーク件数を導く)は、**導出の前提(営業日数・時間帯集中率 等)を選択根拠列に書く**。前提が上流にないものは仮置きとなるため要確認マーカーを付す。
- 上流に出典がないレベル値・数値は、**すべてインライン要確認マーカーを付す**(記法は CLAUDE.md §3)。IPA の全メトリクスに対し上流の非機能要求は限られるため、本書はマーカーが多数残った状態で初版とし、経営・業務部門との合意を経て解消する前提で作る。

### 網羅(トレーサビリティ)

本書は非機能の水準を **システム全体に対して** 定めるため、上流 ID の全件網羅は対象を限定する(CLAUDE.md §11 の本成果物における適用)。

- **全件網羅の対象**: `DOM-COMMON-NFR-*` / `DOM-COMMON-SEC-*` / `DOM-COMMON-SEC-DATA-*` / `DOM-COMMON-REG-*` / `EXT-*`。これらはすべて、いずれかの行の関連 ID 列に少なくとも 1 回現れること。
- **全件網羅の対象外**: `FUNC-*` / `UC-*` / `ACT-*` / `DOM-<コード>-*`(ドメイン個別)。非機能は原則システム全体に効くため、適用範囲を特定機能・特定ドメイン・特定アクターに限定する行でのみ引く。
- グレード表の全メトリクスが、行として存在するか §対象範囲と対象外メトリクス に対象外として記載されているかのいずれかであること(どちらにも現れないメトリクスを残さない)。
