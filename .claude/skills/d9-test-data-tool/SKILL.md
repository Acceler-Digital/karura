# D9: テストデータ作成ツール

## 遵守すべき重要ルール

1. **列は ER図の属性名で記載する**: テストデータテンプレートの列は、ER図の属性名にする。ER図が無ければ概念データモデルの名前にする。テーブル名・カラム名は記載しない。
2. **仕様と画面と初期投入データから決まる値は記載する**: 一意に決まる値は記載する。決まらない値は、決め方を記載する。
3. **要件定義書の範囲の外に出ない**: 要件定義書に無い要件から表を作らない。
4. **上流の成果物を直さない**: 上流の漏れや誤りに気づいたら、直さずにユーザーへ伝える。
5. **ID を振り直さない**: 採番済みの `TDT-*` は変えず、欠番も再利用しない。

## 処理

### 1. 分岐する

- もし `docs/D9.test-design/test-data-requirements.md` が無いなら、テストデータ要件定義書が先である旨を伝えて終了する。
- もし `docs/D9.test-design/test-data-tool.md` が無いなら、§2（新規作成）に進む。
- それ以外なら、§3（更新）に進む。

### 2. 新規作成

#### 2.1 テストデータ作成要否の表を記載する

要件定義書の `TDR-*` を上から、1行ずつテストデータ作成要否の表に記載する。関連要件IDとエンティティは要件から引く。

- **必要**: 手順を始める前に、テストデータを用意しておく必要がある。
- **不要**: 手順を始める前に、テストデータを用意しなくてよい。用意する行が無いとき、手順の中でできるとき、起動時に既にあるとき。
- **作成方法**: 必要な行は「手動」か「スクリプト」、不要な行は「—」とする。画面の操作だけで手順を始める前の状態にできるときは「手動」。画面の操作だけでは用意しにくいとき、データ数が多いときは「スクリプト」。

#### 2.2 テストデータテンプレートを記載する

2.1 で作成方法をスクリプトとした要件を上から進め、要件ごとに1つの見出しと、条件の表と、テストデータテンプレートを記載する。不要な要件と、作成方法が手動の要件は、テストデータテンプレートを記載しない。エンティティ名は要件から引き、ER図の名前と食い違うなら直さずにユーザーへ伝える。ER図が無ければ概念データモデルの名前を見る。条件の表の依存のエンティティが、テストデータ作成要否の表に無いときは、直さずにユーザーへ伝える。

- **条件の表**: 関連要件ID、必要な状態、件数、属性（値）の条件、依存、関連テスト観点を、要件から引く。
- **テストデータテンプレートの列**: ER図でそのエンティティが持つ属性を、図の並びで列にする。ER図が無ければ概念データモデルの属性を使う。
- **テストデータテンプレートの行**: 必要な状態に業務状態の名前があるときは、その名前を業務状態の列に記載し、1状態1行にする。必要な状態に業務状態の名前が無いときは、件数を満たす行を記載する。
- **値**: 画面設計書の表示内容を記載する。画面設計書が無いときは、ワイヤーフレームの表示内容を使う。属性（値）の条件が求めている内容は、画面の表示から記載する。複数の値は「／」でつなぐ。初期投入データから決まる識別子は引く。初期投入データが無いときは、識別子の列は空欄にする。その場で採番する値は「｛自動採番｝」を記載する。日時の列は、決め方を「｛｝」で記載する。

#### 2.3 仕上げる

`TDT-*` をテストデータ作成要否の表の上から通し連番で振る。作成方法がスクリプトの行は、テストデータテンプレートの見出しにも同じ ID を記載する。そのあと「完成時のセルフチェック」を実施する。

### 3. 更新

- インプットした成果物で変わった箇所に関わる行とテストデータテンプレートを §2 の手順で見直す。新しい行には最大値の次の ID を振り、不要になった行とテストデータテンプレートは削除する。
- すでに埋まった値は消さない。
- もし要件を追加・削除・変更したなら、その旨をユーザーに伝える。

## 完成時のセルフチェック

- 要件定義書の全 `TDR-*` が、テストデータ作成要否の表の関連要件IDに現れている
- テストデータ作成要否の表の関連要件IDに、要件定義書に無い `TDR-*` が現れていない
- テストデータ作成要否の表の全行に `TDT-*` がある
- 作成方法がスクリプトの行だけが、テストデータテンプレートの関連要件IDに現れている
- テストデータテンプレートの見出しの `TDT-*` が、作成方法がスクリプトの行の ID と一致している
- 用意する行が無い、手順の中でできる、起動時に既にある、のいずれかの行が、作成要否は不要になっており、作成方法が「—」になっている
- 作成要否が必要の行の作成方法が、「手動」か「スクリプト」になっている
- テストデータテンプレートの列が、そのエンティティについて ER図が定めた属性と一致している
- テーブル名・カラム名が記載されていない
- 画面の表示内容が、テストデータテンプレートに記載されている
- 初期投入データがあるときは、その識別子がテストデータテンプレートに記載されている。無いときは、識別子の列が空欄になっている
- その場で採番する値が「｛自動採番｝」になっている。日時の列に決め方が記載されている
- 条件の表の関連要件ID・必要な状態・件数・属性（値）の条件・依存・関連テスト観点が埋まっており、「同上」等で省略されていない
- 条件の表の依存のエンティティが、テストデータ作成要否の表に無いときは、その旨をユーザーへ伝えている
- `TDT-*` に重複が無い。更新時は既存の ID と行の対応が変わっていない
